Development sources

The functional name Reference Work describes the practice this skill implements: find actual works, inspect them, and refer their useful properties to a new task. It avoids attaching a universal aesthetic or quality claim to a proper name.

Selected upstream skill material was read during development. The following ideas informed original instructions; no upstream code or prose is bundled as this project's original implementation.

  • Impeccable, source/skill/reference/new-work.md: adopted respect for an established identity and derivation from concrete subject material. Its prescribed direction tournament and randomized concept machinery were not needed for this broader workflow.
  • Anthropic frontend-design: adopted subject-specific choices, actual-content construction, and critique of the artifact as built. Broader media require their own evidence, so UI styling prescriptions were not generalized.
  • Taste Skill, skills/taste-skill/SKILL.md: adopted attention to audience, supplied references, and preserved assets. Numeric aesthetic dials and look presets would narrow this skill's judgment and are not used.
  • Vercel web-design-guidelines: adopted compact routing to task-specific source material and concrete findings. Interface compliance is one kind of validation and does not stand in for creative quality.
  • Remotion skills, skills/remotion-best-practices/SKILL.md: adopted selective loading of medium-specific guidance. This package does not require Remotion or reproduce its framework rules.
  • OpenAI's installed skill-creator guidance informed a lean entrypoint, progressive disclosure, portable metadata, and plumbing checks separated from behavioral evaluation.

These are design rationales, not benchmark results. Catalog inspection provenance accompanies records. See the comparison evidence for actual artifacts, conditions, failures, and disagreements.

Using the developing skill

The helper was used on this package itself with a separate private project history. Searching construction/layers/reveal exposed working examples, and using collection discovery exposed a missing route from the entrypoint to the collection directory. That friction led to the sources command and linked discovery routes before the candidate was frozen.

Two inspected works informed the public library: Nicky Case’s Nutshell showed contextual disclosure without losing a reader’s place; the library keeps inspection and rights details within expandable records. Low-tech Magazine’s compressed book article supported lightweight local previews with original sources available on demand. The implementation adapts those properties to a searchable catalog rather than reproducing either source’s appearance. Source-specific inspection locations remain in the catalog.

The name describes a library practice and a working method. It is intentionally a functional title; naming quality was not separately evaluated. The library’s documentation and interface were developed through the same source-property/application/adaptation process.
